About this site

This is an unofficial, independently built companion site for the paper below. It is not part of the paper's official publication and was built to make the ideas explorable, not to replace reading it.

Towards Decentralized Feature Models

Mukelabai Mukelabai, Johan Martinson, Wardah Mahmood, Thorsten Berger, Rafael Capilla

Variability 2026 (Springer LNCS)

Final citation details (pages, DOI) are set upon publication.

Abstract

Feature models are foundational to variability management, yet most existing techniques assume a conceptually single feature model — even when technically partitioned across files or views. This assumption is increasingly misaligned with modular and ecosystem-scale development, where variability is distributed across subsystems owned and evolved by different teams. This paper advances the notion of decentralized feature modeling, in which multiple asset-level feature models coexist, each with an explicit scope and owner, and global consistency is achieved through capability-based cross-model constraints rather than reconstruction of a monolithic model. It demonstrates how decentralized models can be structured, how capabilities express cross-team dependencies, and how distributed configuration ensures global satisfiability while preserving local autonomy. No existing modular, multi-view, or multi-level feature modeling technique fully addresses placement, independent configuration, and incremental analysis in an integrated manner — the paper derives requirements for decentralized modeling and identifies research challenges around decomposition, capability governance, cross-model reasoning, and scalable distributed analysis.

What this site adds, and what it changes

  • The phone example (definition, capability wiring, formulas) is reproduced from the paper as data, and rendered as live, interactive SVG rather than the paper's static figures.
  • The layered-platform example is a synthetic, generalized illustration of a real architectural pattern — no real company, tenant, service, or repository names appear anywhere on this site.
  • The open-source distribution example is original to this site, built from real anchors (Kconfig's depends on INET, package Provides:/Requires: metadata) the paper cites as informal precedent for capabilities.
  • The guided tour, sandbox editor, and share links are original interactive additions — the paper itself is a vision/survey paper with no prototype.
